## ۱. مقدمه

### ۱.۱. هدف

این سند نیازمندی‌های **Task Manager** را مشخص می‌کند؛ برنامه‌ای برای مدیریت وظایف که برای یک کاربر طراحی شده، مبتنی بر خط فرمان است و با Java Standard Edition نوشته می‌شود. برنامه باید بدون هیچ چارچوب نرم‌افزاری یا کتابخانه‌ی شخص ثالثی پیاده‌سازی شود؛ در کد محصول فقط می‌توان از کلاس‌های کتابخانه‌ی Java Class Library (یعنی `java.*` و `javax.*` موجود در JDK) استفاده کرد.

### ۱.۲. محدوده

این سیستم به یک کاربر محلی امکان می‌دهد ثبت‌نام کند، وارد سیستم شود و فهرست شخصی وظایف خود را مدیریت کند. هر وظیفه دارای عنوان، توضیحات، تاریخ سررسید، اولویت، وضعیت، دسته‌بندی و مجموعه‌ای دلخواه از برچسب‌ها است. امکان جست‌وجو، فیلترکردن، مرتب‌سازی و تهیه‌ی گزارش از وظایف وجود دارد. تمام داده‌ها بین نشست‌های استفاده، به‌صورت محلی و در فایل‌های متنی ساده ذخیره می‌شوند.

**موارد مشمول محدوده**

- حساب‌های کاربری محلی (ثبت‌نام، ورود و خروج از سیستم).
- ایجاد، خواندن، به‌روزرسانی و حذف وظایف (CRUD).
- ویژگی‌های وظیفه: عنوان، توضیحات، تاریخ سررسید، اولویت، وضعیت، دسته‌بندی، برچسب‌ها و مُهرهای زمانی.
- گردش کار وضعیت: `TODO → IN_PROGRESS → DONE`، به‌علاوه‌ی `CANCELLED`.
- جست‌وجو، فیلترکردن و مرتب‌سازی فهرست وظایف.
- مدیریت دسته‌بندی‌ها و برچسب‌ها.
- نمایش یادآوری‌های تاریخ سررسید هنگام راه‌اندازی برنامه و بنا به درخواست کاربر.
- آمار (تعداد وظایف در هر وضعیت، نرخ تکمیل و فهرست وظایف سررسیدگذشته).
- ذخیره‌سازی مبتنی بر فایل، همراه با بارگذاری هنگام راه‌اندازی و ذخیره پس از هر تغییر.

**موارد خارج از محدوده**

- عملکرد کارخواه/کارساز (Client/Server)، شبکه و دسترسی هم‌زمان چند کاربر.
- هرگونه پایگاه داده‌ی رابطه‌ای یا ORM.
- رابط‌های وب یا موبایل و هرگونه چارچوب رابط کاربری گرافیکی (GUI).
- همگام‌سازی با تقویم و اعلان‌های ایمیلی یا پیامکی (SMS).
- پیوست فایل، اشتراک‌گذاری وظایف، زیروظیفه‌ها و وظایف تکرارشونده (این موارد برای نسخه‌ای در آینده در نظر گرفته شده‌اند).

### ۱.۳. تعاریف، سرواژه‌ها و اختصارات

| اصطلاح | تعریف |
|---|---|
| **Task (وظیفه)** | واحدی از کار که دقیقاً به یک کاربر تعلق دارد. |
| **Category (دسته‌بندی)** | گروهی از وظایف که کاربر تعریف می‌کند؛ هر وظیفه دقیقاً به یک دسته‌بندی تعلق دارد. |
| **Tag (برچسب)** | برچسبی با نام دلخواه؛ هر وظیفه می‌تواند صفر یا چند برچسب داشته باشد. |
| **Priority (اولویت)** | نوع شمارشی شامل `LOW`، `MEDIUM`، `HIGH` و `URGENT`. |
| **Status (وضعیت)** | نوع شمارشی شامل `TODO`، `IN_PROGRESS`، `DONE` و `CANCELLED`. |
| **Repository (مخزن)** | رابطی که جزئیات ماندگارسازی یک موجودیت دامنه را انتزاع می‌کند. |
| **Service (سرویس)** | کلاسی که قواعد کسب‌وکار را در خود نگه می‌دارد و لایه‌ی رابط کاربری آن را فراخوانی می‌کند. |
| **FR / NFR** | نیازمندی کارکردی / نیازمندی غیرکارکردی. |
| **UC** | مورد کاربرد (Use Case). |
| **JDK** | کیت توسعه‌ی Java (نسخه‌ی ۱۷ یا جدیدتر). |

## ۲. شرح کلی

### ۲.۱. دیدگاه محصول

Task Manager یک برنامه‌ی دسکتاپ مستقل و خودکفا است. این برنامه در چهار لایه سازمان‌دهی شده است و هر لایه فقط به لایه‌ی پایین‌تر از خود وابستگی دارد:

1. **ارائه (Presentation)** — `ConsoleUI`: منوها، تجزیه‌ی ورودی و قالب‌بندی خروجی.
2. **سرویس (Service)** — `AuthService`، `TaskService`، `ReminderService` و `ReportService`: قواعد کسب‌وکار و اعتبارسنجی.
3. **دامنه (Domain)** — `User`، `Task`، `Category`، `Tag`، `Priority` و `Status`: اشیای ساده‌ی جاوا که از جزئیات ذخیره‌سازی اطلاعی ندارند.
4. **ماندگارسازی (Persistence)** — رابط‌های `TaskRepository` و `UserRepository` و پیاده‌سازی‌های مبتنی بر فایل آن‌ها (`FileTaskRepository` و `FileUserRepository`) که بر پایه‌ی کلاس کاربردی `FileStorage` ساخته شده‌اند.

هیچ لایه‌ای نباید به لایه‌ای بالاتر از خود ارجاع دهد. مخزن‌ها پشت رابط‌ها پنهان شده‌اند تا بتوان سازوکار ذخیره‌سازی را بدون تغییر لایه‌های سرویس یا رابط کاربری جایگزین کرد.

### ۲.۲. کارکردهای محصول

- **مدیریت حساب کاربری:** ثبت‌نام، ورود و خروج از سیستم.
- **چرخه‌ی حیات وظیفه:** ایجاد، نمایش فهرست، مشاهده، ویرایش، حذف و تغییر وضعیت وظیفه.
- **سازمان‌دهی:** مدیریت دسته‌بندی‌ها و برچسب‌ها.
- **بازیابی اطلاعات:** جست‌وجو با کلمات کلیدی، فیلتر بر اساس وضعیت، اولویت، دسته‌بندی یا تاریخ سررسید و مرتب‌سازی بر اساس تاریخ سررسید، اولویت یا تاریخ ایجاد.
- **آگاهی‌رسانی:** یادآوری تاریخ سررسید و مشخص‌کردن وظایف سررسیدگذشته.
- **تحلیل و بینش:** ارائه‌ی آمار و گزارش‌ها.
- **ماندگاری داده‌ها:** بارگذاری خودکار هنگام راه‌اندازی و ذخیره پس از هر تغییر در داده‌ها.

### ۲.۳. ویژگی‌های کاربران

این سیستم برای یک کاربر آشنا به فناوری (مالک دستگاه) طراحی شده است که با کار در محیط ترمینال راحت باشد. آشنایی فراتر از منوی روی صفحه و فرمان راهنمای داخلی برنامه لازم نیست.

### ۲.۴. محیط عملیاتی

- **محیط اجرا:** محیط اجرای Java SE نسخه‌ی ۱۷ یا جدیدتر.
- **سیستم‌عامل:** هر پلتفرمی که ماشین مجازی جاوا (JVM) داشته باشد؛ از جمله Windows، Linux و macOS.
- **نمایشگر:** ترمینال متنی با پشتیبانی از UTF-8.
- **ذخیره‌سازی:** دسترسی خواندن و نوشتن به یک پوشه‌ی داده‌ی برنامه.

### ۲.۵. محدودیت‌های طراحی و پیاده‌سازی

- **بدون چارچوب نرم‌افزاری و کتابخانه‌ی شخص ثالث.** استفاده از Spring، Jakarta EE، Hibernate، JavaFX، ‏JUnit (در کد محصول)، Gson و موارد مشابه ممنوع است. فقط کتابخانه‌ی کلاس‌های JDK مجاز است.
- **بدون پایگاه داده.** داده‌ها در فایل‌های متنی ساده ذخیره می‌شوند و مدیریت آن‌ها با `java.nio.file` و `java.io` انجام می‌شود.
- **بدون چارچوب رابط کاربری گرافیکی.** رابط کاربری مبتنی بر کنسول است. استفاده از `javax.swing` فقط در قالب یک ماژول توسعه‌ای اختیاری و کاملاً مجزا مجاز است.
- **سطح زبانی Java 17،** با استفاده‌ی مناسب از `record`ها، عبارت‌های `switch` و API مربوط به `java.time`.
- **معماری لایه‌ای،** همراه با وارونگی وابستگی در مرز ذخیره‌سازی (رابط‌های مخزن).
- کد باید از **قراردادهای نام‌گذاری Java در Sun/Oracle** پیروی کند و با **Javadoc** مستندسازی شود.

### ۲.۶. فرضیات و وابستگی‌ها

- در هر لحظه فقط یک نمایه‌ی کاربری فعال است؛ دسترسی هم‌زمان از دو فرایند پشتیبانی نمی‌شود.
- گذرواژه‌ها با الگوریتم **SHA-256** و با استفاده از یک مقدار salt تصادفیِ مختص هر کاربر هش می‌شوند؛ گذرواژه‌ی خام هرگز ذخیره نمی‌شود.
- پوشه‌ی داده قابل نوشتن است و از طریق درایو شبکه به اشتراک گذاشته نشده است.
- ساعت سیستم درست است؛ منطق مربوط به تاریخ سررسید به `LocalDate.now()` متکی است.

### ۳.۳. موارد کاربرد با جزئیات

#### ۳.۳.۱. UC-01 — ثبت حساب کاربری

**عامل‌ها:** کاربر.

**پیش‌شرط‌ها:** هیچ نشستی فعال نیست.

**جریان اصلی**

1. کاربر گزینه‌ی «ثبت‌نام» را انتخاب می‌کند.
2. سیستم نام کاربری و گذرواژه را دو بار درخواست می‌کند.
3. سیستم بررسی می‌کند که نام کاربری یکتا باشد، دو بار واردکردن گذرواژه یکسان باشد و گذرواژه حداقل ۸ نویسه داشته باشد.
4. سیستم یک salt تصادفی تولید می‌کند و هشِ دارای salt و رکورد کاربر را ذخیره می‌کند.
5. سیستم موفقیت‌آمیزبودن ثبت‌نام را تأیید می‌کند.

**جریان‌های جایگزین**

- **۳الف.** نام کاربری قبلاً انتخاب شده است ← خطا نمایش داده می‌شود و فرایند به مرحله‌ی ۲ بازمی‌گردد.
- **۳ب.** گذرواژه‌ها یکسان نیستند ← خطا نمایش داده می‌شود و فرایند به مرحله‌ی ۲ بازمی‌گردد.
- **۳پ.** گذرواژه بیش از حد کوتاه است ← خطا نمایش داده می‌شود و فرایند به مرحله‌ی ۲ بازمی‌گردد.

**پس‌شرط‌ها:** رکورد کاربر جدیدی در `users.dat` وجود دارد.

#### ۳.۳.۲. UC-02 — ورود به سیستم

**عامل‌ها:** کاربر، زمان‌بند.

**پیش‌شرط‌ها:** دست‌کم یک کاربر ثبت‌نام کرده است.

**جریان اصلی**

1. کاربر نام کاربری و گذرواژه را وارد می‌کند.
2. سیستم کاربر را پیدا می‌کند، گذرواژه‌ی واردشده را با salt ذخیره‌شده هش می‌کند و نتیجه را مقایسه می‌کند.
3. در صورت موفقیت، نشست ایجاد می‌شود، منوی اصلی نمایش داده می‌شود و بررسی یادآوری‌ها فعال می‌شود.

**جریان‌های جایگزین**

- **۲الف.** نام کاربری ناشناخته است یا گذرواژه اشتباه است ← خطای عمومی «اطلاعات ورود نامعتبر است» نمایش داده می‌شود و نشستی ایجاد نمی‌شود.

**پس‌شرط‌ها:** نشست ایجاد شده است و منوی اصلی نمایش داده می‌شود.

#### ۳.۳.۳. UC-03 — ایجاد وظیفه

**عامل‌ها:** کاربر.

**پیش‌شرط‌ها:** کاربر وارد سیستم شده است.

**جریان اصلی**

1. کاربر گزینه‌ی «ایجاد وظیفه» را انتخاب می‌کند.
2. سیستم عنوان، توضیحات، تاریخ سررسید، اولویت، دسته‌بندی و برچسب‌ها را درخواست می‌کند.
3. کاربر داده‌ها را وارد می‌کند.
4. سیستم ورودی را اعتبارسنجی می‌کند.
5. سیستم یک `Task` با شناسه‌ی تولیدشده و وضعیت `TODO` ایجاد می‌کند.
6. `TaskService` کار را به `TaskRepository` واگذار می‌کند.
7. `FileTaskRepository` وظیفه را به‌صورت اتمی در `tasks.dat` می‌نویسد.
8. سیستم پیام تأییدی همراه با شناسه‌ی جدید را نمایش می‌دهد.

**جریان‌های جایگزین**

- **۴الف.** اعتبارسنجی ناموفق است ← پیام خطا نمایش داده می‌شود و اطلاعات از مرحله‌ی ۲ دوباره درخواست می‌شوند.
- **۷الف.** خطای نوشتن رخ می‌دهد ← پیام خطای ذخیره‌سازی نمایش داده می‌شود؛ وظیفه در حافظه باقی می‌ماند و کاربر می‌تواند دوباره تلاش کند.

**پس‌شرط‌ها:** وظیفه هم در حافظه و هم روی دیسک وجود دارد.

#### ۳.۳.۴. UC-04 — جست‌وجو و فیلترکردن وظایف

**عامل‌ها:** کاربر.

**پیش‌شرط‌ها:** کاربر وارد سیستم شده است.

**جریان اصلی**

1. کاربر گزینه‌ی «جست‌وجو / فیلتر» را انتخاب می‌کند.
2. سیستم یک کلمه‌ی کلیدی و/یا معیارهای فیلتر را درخواست می‌کند.
3. سیستم معیارها را روی وظایف کاربر اعمال می‌کند.
4. سیستم نتایج را در قالب جدولی شماره‌گذاری‌شده نمایش می‌دهد.

**جریان‌های جایگزین**

- **۳الف.** هیچ وظیفه‌ای با معیارها مطابقت ندارد ← پیام «هیچ وظیفه‌ی منطبقی یافت نشد» نمایش داده می‌شود.
- **۳ب.** قالب تاریخ نامعتبر است ← خطای اعتبارسنجی نمایش داده می‌شود و فرایند به مرحله‌ی ۲ بازمی‌گردد.

**پس‌شرط‌ها:** فهرست نتایج نمایش داده می‌شود و هیچ داده‌ای تغییر نمی‌کند.

#### ۳.۳.۵. UC-05 — تغییر وضعیت وظیفه

**عامل‌ها:** کاربر.

**پیش‌شرط‌ها:** کاربر وارد سیستم شده و دست‌کم یک وظیفه وجود دارد.

**جریان اصلی**

1. کاربر گزینه‌ی «تغییر وضعیت» و شناسه‌ی یک وظیفه را انتخاب می‌کند.
2. سیستم بررسی می‌کند که تغییر وضعیت درخواستی مجاز باشد.
3. سیستم وضعیت را به‌روزرسانی می‌کند و اگر وضعیت `DONE` باشد، مقدار `completedAt` را تنظیم می‌کند.
4. سیستم تغییر را ذخیره و آن را تأیید می‌کند.

**جریان‌های جایگزین**

- **۲الف.** تغییر وضعیت غیرمجاز است (برای مثال `DONE → TODO`) ← خطا نمایش داده می‌شود و تغییری انجام نمی‌شود.

**پس‌شرط‌ها:** وضعیت و مُهر زمانی روی دیسک به‌روزرسانی شده‌اند.

#### ۳.۳.۶. UC-06 — دریافت یادآوری سررسید

**عامل‌ها:** زمان‌بند (آغازکننده)، کاربر (مشاهده‌کننده).

**پیش‌شرط‌ها:** کاربر وارد سیستم شده است.

**جریان اصلی**

1. زمان‌بند، `ReminderService` را فعال می‌کند.
2. سرویس، وظایفی را جمع‌آوری می‌کند که سررسید آن‌ها گذشته یا در ۲۴ ساعت آینده است و وضعیتشان `DONE` یا `CANCELLED` نیست.
3. سیستم فهرست یادآوری را چاپ می‌کند و وظایف سررسیدگذشته را با علامت `!` مشخص می‌کند.

**جریان‌های جایگزین**

- **۲الف.** هیچ وظیفه‌ای واجد شرایط نیست ← چیزی چاپ نمی‌شود.

**پس‌شرط‌ها:** فهرست یادآوری نمایش داده شده است و هیچ داده‌ای تغییر نکرده است.

## ۵. نیازمندی‌های رابط خارجی

### ۵.۱. رابط کاربری

رابط کاربری یک منوی متنی است. نمونه‌ای از یک نشست معمولی در ادامه آمده است:

```text
مدیر وظایف - alice (۳ وظیفه سررسیدشده)

 1) فهرست وظایف       6) جست‌وجو / فیلتر
 2) ایجاد وظیفه       7) دسته‌بندی‌ها
 3) نمایش وظیفه       8) برچسب‌ها
 4) به‌روزرسانی وظیفه  9) آمار
 5) حذف وظیفه        10) یادآوری‌ها
                     11) خروج از سیستم
                      0) راهنما

> 2
عنوان: تدوین SRS
تاریخ سررسید (YYYY-MM-DD، خالی = بدون تاریخ): 2025-02-01
اولویت (LOW/MEDIUM/HIGH/URGENT): HIGH
دسته‌بندی (خالی = بدون دسته‌بندی): دانشگاه
برچسب‌ها (جداشده با ویرگول): design,srs

>> وظیفه‌ی T2001 ایجاد شد (وضعیت TODO).
```

### ۵.۲. رابط‌های سخت‌افزاری و نرم‌افزاری

- ماشین مجازی جاوا (JVM) نسخه‌ی ۱۷ یا جدیدتر که `java.base` را فراهم کند.
- جریان‌های ورودی استاندارد و خروجی استاندارد.
- سیستم فایل محلی برای سه فایل داده‌ای که در بخش ۶ شرح داده شده‌اند.

### ۵.۳. رابط‌های ارتباطی

هیچ‌کدام. برنامه هیچ ارتباط شبکه‌ای برقرار نمی‌کند.

## ۶. نیازمندی‌های داده

### ۶.۱. موجودیت‌های دامنه

- **`User` (کاربر):** شناسه، نام کاربری (یکتا)، `passwordHash`، مقدار `salt` و `createdAt`.
- **`Task` (وظیفه):** شناسه، عنوان، توضیحات، `dueDate`، اولویت، وضعیت، `createdAt`، `completedAt`، `userId`، `categoryId` و برچسب‌ها.
- **`Category` (دسته‌بندی):** شناسه، نام (یکتا برای هر کاربر)، رنگ و `userId`.
- **`Tag` (برچسب):** نام (یکتا برای هر کاربر).

### ۶.۲. قالب ذخیره‌سازی

داده‌ها در سه فایل متنی UTF-8 قرار می‌گیرند که فیلدهای آن‌ها با نویسه‌ی pipe (`|`) از هم جدا شده‌اند. خط اول هر فایل، سرآیند نسخه‌ی قالب است.

**`users.dat`**

```text
# v1
U1001|alice|9f2c...|3b71...|2025-01-15
```

**`tasks.dat`**

```text
# v1
T2001|U1001|Write SRS|Chapter 1-8|2025-02-01|HIGH|TODO|C3001|design,srs|2025-01-16|
```

**`categories.dat`**

```text
# v1
C3001|U1001|University|#3366cc
```

فیلدها نباید حاوی جداکننده‌ی `|` باشند؛ هنگام نوشتن، این نویسه به شکل `\p` گریزدهی می‌شود و هنگام خواندن، از حالت گریز خارج می‌شود.

### ۶.۳. قواعد یکپارچگی داده‌ها

1. هر وظیفه همیشه دقیقاً به یک کاربر موجود تعلق دارد.
2. دسته‌بندی یک وظیفه یا خالی است یا به دسته‌بندی موجودی از همان کاربر اشاره می‌کند.
3. مقدار `completedAt` اگر و تنها اگر وضعیت `DONE` باشد تنظیم می‌شود.
4. شناسه‌ها یکتا هستند و درون یک فایل هرگز دوباره استفاده نمی‌شوند.
5. هنگام بارگذاری، خطوط دارای قالب نامعتبر نادیده گرفته و گزارش می‌شوند؛ پذیرش آن‌ها نباید بی‌صدا انجام شود.

## ۷. نمای کلی معماری سیستم

سیستم در چهار لایه سازمان‌دهی شده است و هر لایه فقط به لایه‌ی پایین‌تر از خود وابستگی دارد.

```text
┌──────────────────────────────────────────────────────┐
│  ارائه (presentation)                                │
│  ConsoleUI                                           │
├──────────────────────────────────────────────────────┤
│  سرویس (service)                                     │
│  AuthService   TaskService                           │
│  ReminderService   ReportService                     │
├──────────────────────────────────────────────────────┤
│  دامنه (domain)                                      │
│  User  Task  Category  Tag                           │
│  Priority  Status (انواع شمارشی)                     │
├──────────────────────────────────────────────────────┤
│  ماندگارسازی (persistence)                            │
│  UserRepository  TaskRepository (رابط‌ها)            │
│  FileUserRepository  FileTaskRepository              │
│  FileStorage (ابزار کمکی)                            │
└──────────────────────────────────────────────────────┘
```

- **ارائه (Presentation)** به سرویس (Service) وابسته است.
- **سرویس (Service)** به دامنه (Domain) و رابط‌های مخزن وابسته است.
- **دامنه (Domain)** به هیچ‌یک از لایه‌های بالاتر وابستگی ندارد.
- **ماندگارسازی (Persistence)** رابط‌های مخزن را پیاده‌سازی می‌کند و فقط به دامنه و `FileStorage` وابسته است.

## ۸. معیارهای پذیرش

سیستم زمانی پذیرفته می‌شود که تمام موارد زیر برقرار باشند:

1. کاربر جدید بتواند ثبت‌نام کند، وارد سیستم شود، خارج شود و در یک فرایند تازه دوباره وارد شود؛ داده‌ها پس از راه‌اندازی مجدد باقی بمانند.
2. تمام عملیات CRUD روی وظایف درست کار کنند و تغییرات بلافاصله روی دیسک منعکس شوند.
3. جست‌وجو، فیلتر و مرتب‌سازی روی مجموعه‌داده‌ای شامل دست‌کم ۱۰۰ وظیفه، زیرمجموعه‌های مورد انتظار را برگردانند.
4. یادآوری‌ها دقیقاً وظایف سررسیدگذشته و وظایفی را که در ۲۴ ساعت آینده سررسید می‌شوند فهرست کنند.
5. ورودی نامعتبر هرگز باعث از کار افتادن برنامه نشود و پیام خطایی خوانا نمایش داده شود.
6. در کد محصول به هیچ کلاسی خارج از `java.*` و `javax.*` موجود در JDK ارجاع داده نشود.
7. نمودار کلاس با بسته‌های پیاده‌سازی‌شده مطابقت داشته باشد.
